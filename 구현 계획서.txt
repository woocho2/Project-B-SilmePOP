[한 판의 흐름] (기획 [7])
  메인 메뉴(색·테마 고르기) → 로그인(닉네임) → 로비(채팅, 방 목록)
  → 대기실(최대 4자리, 방장이 AI 추가·난이도, 준비, 채팅)
  → 방장이 시작: 시드, 목표 합(10 ~ 15), 시작 시각을 방에 기록
  → 모든 참가자가 같은 시각에 목표 합 공개 → 카운트다운 3, 2, 1
  → 120초 플레이 (각자 자기 판. 점수만 실시간 공유. 채팅 가능)
  → 결과(1 ~ 4위, 각자의 최종 판, 채팅) → 재대결(대기실) / 로비

[참가자 셋 — 점수는 모두 네트워크를 거침]
  내 판        이 PC에서 사람이 푸는 판. 점수를 서버에 올림
  다른 사람    다른 PC에서 푸는 판. 이 PC는 점수만 받음 (판은 결과 화면에서만 받음)
  AI           방장 PC에서 AiPlayer가 푸는 판. 방장이 대신 점수를 서버에 올림
  → 점수판은 "서버에서 온 점수"만 보면 됨. 사람이든 AI든 같은 길.
  ※ 기획 [8]의 IOpponent는 이 구조로 바꿈: 상대마다 객체를 두지 않고, 모든 점수가 INetworkService를 거침.
     4인 + 방장 PC의 AI라서 이쪽이 단순함. (기획.txt [8]도 같이 고침)

[매니저 6개 — 누가 무엇의 주인인가]
  GameManager      한 판의 진행: 시작 시각 대기, 목표 합 공개, 카운트다운, 120초, 종료, 순위 확정, 최종 판 올리기

  DragManager      드래그 입력과 판정 (놓는 순간 범위 안 칸 → 슬라임 → 합 → 점수)
  SkillManager     내 스킬 6종: 단축키, 대상 고르기 모드, 범위 미리보기, 사용
  NetworkManager   접속, 내 정보, 지금 방, 채팅, 점수·최종 판 송수신, 서버 시간 (씬을 넘어 유지)
  SoundManager     (지금 것 그대로)
  + 씬마다 UI 매니저 하나: UIManager_Start / _Menu / _Lobby / _Room / _Game

[스크립트를 나누는 다섯 가지 역할]
  데이터   원본 값. 판 도중 바뀌지 않음 (GameRules, SlimeSkinCatalog, ThemeData, AiDifficultyTable)
  상태     판 도중 바뀌는 값. 값마다 주인이 하나 (BoardModel, SkillSet, MatchScores)

3. 쓰는 패턴과 쓰지 않는 것
======================================================================

[규칙과 화면 분리] (가장 중요)
  BoardModel(순수 C#)이 판의 진짜 상태. SlimeManager/SlimeController는 BoardModel의 이벤트를 듣고 그리기만 함.
  왜: AI 판은 화면이 없음(미니맵 없음). 시뮬레이션은 수천 판을 화면 없이 돌림. 테스트는 MonoBehaviour 없이 돌림.

[싱글톤] 매니저 6개 + 씬 UI 매니저. Singleton<T>를 물려받음.
  NetworkManager·SoundManager만 DontDestroyOnLoad (씬을 넘어 접속이 유지돼야 함). 나머지는 씬 단위.
  계산·상태 클래스는 싱글톤으로 만들지 않음 (인자로 받아야 테스트 가능).

[전략 패턴] 스킬 6종. SkillBase(대상 가능 여부, 범위, 적용)를 종류마다 채움.
  왜: 사람(SkillManager)과 AI(AiBrain)가 같은 스킬 클래스를 씀. switch로 하면 두 곳을 같이 고쳐야 함.

[인터페이스] INetworkService. LocalNetworkService(서버 없이, 메모리) / FirebaseNetworkService(실제).
  왜: 과제 요구사항이 아직 미발표. 게임 코드는 인터페이스만 알면 구현을 바꿔도 안 고침.
      서버 없이 혼자 대기실 → 대전 → 결과를 끝까지 만들 수 있음 (AI만 넣고).

[옵저버 (C# event)] BoardModel → 화면, NetworkManager → UI, GameManager → UI.
  조심: 구독(+=)과 해제(-=)는 짝으로 (OnEnable/OnDisable 또는 Start/OnDestroy).
        네트워크 콜백은 메인 스레드가 아닐 수 있음 → NetworkManager가 큐에 담아 Update에서 이벤트를 쏨.

[시드 랜덤] GameRandom(System.Random 래퍼). UnityEngine.Random은 규칙 코드에서 쓰지 않음.
  판 생성: 방의 seed. 스킬·조커 이동: seed와 자리 번호로 만든 참가자별 시드 (같은 판이어도 참가자마다 다르게).

쓰지 않는 것: 오브젝트 풀(슬라임 170개를 한 판에 한 번 만듦. 재대결 때 다시 만드는 비용이 작음),
              상태 패턴(게임 상태가 대기/카운트다운/진행/종료 넷뿐 → enum), DOTween(새 패키지를 들일 시간 없음. 연출은 코루틴).

----------------------------------------------------------------------
[4-1] 칸과 좌표
----------------------------------------------------------------------
  - 판 17 x 10. 칸 좌표 (x 0 ~ 16, y 0 ~ 9), 칸 번호 = y * 17 + x (0 ~ 169). 네트워크·스냅샷은 칸 번호로 보냄.
  - 칸 → 슬라임은 BoardModel.GetSlimeAt(cell). 빈칸은 null.
  - 합체 슬라임: 네 칸이 같은 BoardSlime을 가리킴. BoardSlime.Cells에 네 칸, Anchor는 왼쪽 아래 칸.
  - 화면: 칸마다 SlimeController 1개(칸 170개 고정, 콜라이더 포함). 슬라임이 없으면 그림과 콜라이더를 끔.
    합체 슬라임은 Anchor 칸이 2 x 2 그림을 그리고, 나머지 세 칸은 그림만 끄고 콜라이더는 켜 둠 (기획 [4-1] 4번).
  - 칸의 콜라이더 크기는 지금처럼 작게(0.1) → 드래그 박스가 "칸 중심"을 덮어야 포함. 그래서 드래그 = 격자 사각형과 같음.

[4-3] 터뜨리기 한 번의 순서 (DragManager → BoardModel)
----------------------------------------------------------------------
  ① 놓는 순간 Physics2D.OverlapBoxAll(드래그 박스) → 칸 목록 (Trigger 누적은 화면 강조용으로만)
  ② 칸 → BoardModel.GetSlimesInCells(칸 목록): 중복 제거 (합체 슬라임 1번만)
  ③ 숫자 합 == TargetSum ? 아니면 실패음, 끝
  ④ ScoreCalculator.Calculate(슬라임들, targetSum) → 점수 (기획 [4-2])
  ⑤ BoardModel.Remove(슬라임들) → SlimesRemoved → 화면 갱신
  ⑥ GameManager.AddScore(점수) → 시각 기록 → NetworkManager.ReportScore
  ⑦ MatchFinder.HasAnyMatch(board, targetSum) == false → NoMoreMoves (조기 종료 없음)
  드래그 중에도 조커는 움직임. 판정은 ①의 순간의 판 기준 (기획 [4-1] 5번).

----------------------------------------------------------------------
[4-4] 점수 계산 (ScoreCalculator, 기획 [4-2] 그대로)
----------------------------------------------------------------------
  B = 슬라임들의 기본점수 합 (기본 1, 악마 1, 천사 2, 킹 1, 조커 3, 합체 = 합쳐진 기본점수 합)
  점수 = B + Σ천사(B x 2) + Σ악마(B x -1) + Σ킹(10) + Σ조커(목표 합 x 2)
  파괴 스킬: 그 슬라임의 기본점수만. 합체 후 0 → 합체된 슬라임 수 x 4.
  기획의 예시 전부를 테스트(T3)로 고정.

----------------------------------------------------------------------
[4-5] 매칭 탐색 (MatchFinder)
----------------------------------------------------------------------
  사각형 개수는 C(18,2) x C(11,2) = 8,415개. 칸 누적합으로 모두 봐도 충분히 빠름 (AI가 매 턴 전부 봄).
  합체 슬라임: 숫자를 Anchor 칸에만 넣고 나머지 세 칸은 0으로 누적합을 만듦.
              사각형이 합체 네 칸 중 하나라도 걸치는데 Anchor를 안 덮으면 그 숫자를 더함 (합체는 한 판에 1번이라 하나만 신경 쓰면 됨).
  빈칸은 0. 슬라임이 하나도 없는 사각형은 제외.
  돌려주는 것: HasAnyMatch, FindFirst(돋보기), FindAll(AI)

----------------------------------------------------------------------
[4-6] 네트워크 흐름 (INetworkService)
----------------------------------------------------------------------
  로그인        SignIn(닉네임) → 내 uid
  로비          LobbyUsersChanged, RoomListChanged, SendChat(Lobby, text)
  방            CreateRoom / JoinRoom / LeaveRoom, SetReady, (방장) AddAi(자리, 난이도) / RemoveAi / StartMatch
                StartMatch: seed, targetSum(10 ~ 15), startAt(서버 시각 + 5초)을 방에 씀 → 모두 MatchStarting을 받음
  대전          ReportScore(자리, 점수, 시각) — 내 자리는 내가, AI 자리는 방장이
                ScoresChanged로 모두의 점수를 받음
  종료          UploadFinalBoard(자리, BoardSnapshot) — 사람은 자기 것, AI는 방장이
                FinalBoardReceived가 다 오거나 5초가 지나면 결과 확정
  끊김·퇴장     하트비트(5초) — 15초 동안 소식이 없으면 끊긴 것으로. 대전 중이면 기권(최하위)
  방장 퇴장     대기실: 사람이 있으면 랜덤 1명에게 방장, AI만 남으면 방 삭제
                대전 중: 그 판은 끝까지. AI 점수는 그 순간에 멈춤. 판이 끝난 뒤 위와 같이 (기획 [6])
  기록 삭제     결과 화면을 나가면 scores, finalBoards를 지움
